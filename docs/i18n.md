# 用户文案与多语言（i18n）

Haruki-Cloud 的所有用户文案都在 `internal/i18n` 里：聊天回复、错误提示、`-help`
帮助文档，以及发给 Drawing 画进图片的标签。规范（术语、标点、格式）见
[`AGENTS.md` §12](../AGENTS.md#12-用户文案规范user-copy)。本文说明怎么增加、审查和翻译文案。

## 目录结构

```
internal/i18n/
├── i18n.go, format.go, messages.go, help.go, lines.go, timeago.go   # 访问接口和共享格式函数
├── locales/
│   └── zh-CN/
│       ├── common.toml       # 兜底错误、错误模板、功能名
│       ├── format.toml       # 区服、账号、时间、时长、数字、分页、难度、Live 类型
│       ├── moderation.toml   # /kill、/back、封禁提示
│       ├── usage.toml        # 帮助文档自动生成的“区服”“指令别名”两节
│       ├── guidance.toml     # 各路由参数无法识别时的引导
│       ├── render*.toml      # 多个图片共用的标签（render.toml）和卡牌图片的标签（render_card.toml）
│       ├── <领域>.toml       # 每个领域一个文件
│       └── help/*.md         # -help 帮助文档，文件名 = 路由路径把 / 换成 _
└── testdata/                 # golden 文件、未使用 ID 允许清单
```

目录和帮助文档通过 `go:embed` 编进二进制。程序启动时加载全部目录，解析失败会直接退出，
测试也会失败。

## 一条消息的写法

```toml
[moderation.kill.done_until]
description = "/kill 限时封禁成功后回复管理员。占位符：QQ=被封禁的 QQ 号；Reason=封禁原因，管理员输入的原文；ExpiresAt=解封时间，按管理员时区格式化。"
other = "已全局封禁 QQ 号 {{.QQ}}\n原因：{{.Reason}}\n解封时间：{{.ExpiresAt}}"
```

- 表名就是消息 ID：`<领域>.<子域>.<名称>`，小写加下划线，第一段等于文件名。
- `description` 写出现位置，再写 `占位符：Name=含义；…`，每个占位符都要写。
- `other` 是文案本身。只用 `{{.Name}}` 占位符，不用 `%s`，不用模板逻辑。
  换行写 `\n`。
- 中文只有 `other` 一种复数形式；其他语言需要复数时再加 `one` 等字段。

## 在代码里使用

```go
import (
    "haruki-cloud/internal/i18n"
    "haruki-cloud/utils/usererror"
)

// 普通回复：渲染成 zh-CN 字符串
text := i18n.T("moderation.back.done", i18n.Data{"QQ": qq})

// 需要延迟渲染或嵌套时用 Message，嵌套的 Message 会按同一语言渲染
msg := i18n.M("moderation.kill.done_until", i18n.Data{
    "QQ":        qq,
    "Reason":    reason,
    "ExpiresAt": i18n.FormatUserTime(expiresAt, displaytime.RequestLocation(ctx)),
})
reply := msg.String()          // 默认语言
reply = msg.In(i18n.ZhCN)      // 指定语言

// 错误：带 Code、目录消息和只进日志的原因
return usererror.BadParam(arg, i18n.M("moderation.qq_invalid"))
return usererror.Usage(i18n.M("moderation.back.usage_reason"), "/back")
return usererror.Misuse(i18n.M("deck.compare.too_many", i18n.Data{"Max": 5}))
return usererror.Unrecognized()                 // 回复层换成该路由的引导
return usererror.Setup(i18n.M("binding.required"))
return usererror.Unavailable(i18n.FeatureRanking, err)
return usererror.Misconfigured(err)             // 服务配置异常，请联系 Bot 管理员
return usererror.Internal(err)
```

- ID 必须写成字符串字面量，占位符写成 `i18n.Data{...}` 字面量，完整性测试才能检查
  ID 是否存在、占位符是否齐全。
- 需要区服、账号、时间、距今多久、时长、数字、百分比、分页、难度、Live 类型时，用
  `internal/i18n` 的函数，不要自己拼（列表见 AGENTS.md §12.1）。
- `usererror.Error` 的 `Error()` 只有用户文案；原因通过 `Unwrap` 和
  `usererror.LogText` 进日志。测试断言 `Code` 和 `Message.ID`
  （`testutil.RequireUserError`）。
- 不是带类型错误的错误不会把文本给用户：回复层先用 `internal/core/upstreamerr`
  给上游错误分类，其余回复“请求处理失败”。回复发出前 `i18n.SanitizeLines`
  会去掉不是目录消息渲染出来的行。
- 帮助文档用 `i18n.HelpDoc(locale, key)` 读取，`key` 是路由路径把 `/` 换成 `_`
  （`deck/event` → `deck_event`）。

## 帮助文档

`<指令> -help` 发送该路由自己的帮助文档（`help/<key>.md`）。每个已注册路由都有一份，
没有路由能显示的文档不允许存在；路由以外只有 `generic.md`（没有路由时的总帮助）和
`mysekai_blueprint.md`（`/msb` 等蓝图写法）。

版式只有一种（`TestHelpDocsFollowLayout`）：

```markdown
# 标题

一句话说明这个指令做什么、需要什么数据（可选，可以两句）。

## 用法
- `/主指令 <必填> [可选] [a|b] [重复…]`

## 参数
- `参数名`：说明（没有参数时写“- 不需要参数”）
### 分组（参数多时可以用三级标题分组）

## 示例
- `/主指令 例子`

## 说明
- 可选：限制、权限、和其他指令的关系
```

- 二级标题只能是“用法、参数、示例、说明”，按这个顺序，前三个必须有。
- 用法里写用户实际发送的指令，写法见 AGENTS.md §12：`<必填>`、`[可选]`、`a|b`、`…`。
- 示例必须真的能用：`TestHelpDocExamplesParse` 把每个示例交给指令解析器，示例必须被
  这个文档的路由接受。示例里的 `@群友` 会当作一次 @；多行指令（例如添加别名）写在
  `示例` 下的代码块里。
- 文档里反引号中的 `/指令` 都必须是已注册的写法（`TestHelpDocTriggersAreRegistered`）。
  用户已经学会的旧写法，没有歧义和冲突时注册成别名，否则改文档。
- 不要手写区服前缀说明和别名列表：发送时自动在末尾加“区服”一节（按 handler 的
  `Regions` 生成，文案在 `usage.toml`）和“指令别名”一节（文档里没出现的其他写法）。
  与区服无关的路由（账号级设置、别名审核、管理）在 `command_help.go` 的
  `regionAgnosticHelpRoutes` 里，不生成“区服”一节。
- 渲染服务不可用时，帮助以纯文字发送：去掉 Markdown 标记，小标题改成“用法：”这种形式。
- 术语按 AGENTS.md §12.5；`TestHelpDocTerms` 和 `TestHelpDocStyle` 检查禁用词、标点和空格。

## 增加或修改文案

1. 在对应领域的 TOML 里加消息（没有合适的文件就新建 `<领域>.toml`）。
2. 在代码里用 `i18n.M`/`i18n.T` 或 `usererror` 引用它，删掉原来的中文字面量。
3. 运行 `go test ./internal/i18n/ ./internal/pjsk/handler/`：
   - `TestCatalogStyle` 检查标点、空格、禁用词、description；
   - `TestCatalogIntegrity` 检查 ID 和占位符，以及有没有没人用的消息；
   - `TestEveryMessageRendersWithSampleData` 用示例数据渲染每条消息；
   - `TestCopylint` 检查 Go 代码里没有中文字面量。
4. 改了共享格式函数的输出或某个领域的回复时，用 `HARUKI_UPDATE_GOLDEN=1 go test ./...`
   重新生成 golden 文件（`internal/i18n/testdata/helpers.zh-CN.golden`、各领域的
   `testdata/replies.zh-CN.golden` 等）并检查 diff。

修改已有措辞只改 `other`，不改 ID。

## 审查文案

只看 `internal/i18n/locales/zh-CN/` 就够了：每条消息的 `description` 写了它出现在哪里、
占位符是什么。共享格式函数的实际输出在 `internal/i18n/testdata/helpers.zh-CN.golden`，
账号绑定和别名的完整回复样例在 `internal/pjsk/accountdata/testdata/replies.zh-CN.golden`
和 `internal/pjsk/alias/testdata/replies.zh-CN.golden`，图片标签的样例在
`internal/pjsk/render/common/testdata/labels.zh-CN.golden`。PR 里文案的变化就是这些文件的 diff。

## 增加一种语言

1. 新建 `internal/i18n/locales/<BCP 47 标签>/`（例如 `en`、`zh-TW`），按领域放 TOML
   文件，ID 和占位符必须与 `zh-CN` 一致（`TestCatalogIntegrity` 会检查）。
   可以只翻译一部分，缺失的消息回退到 `zh-CN`。
2. 帮助文档放在 `<标签>/help/` 下，同样可以只翻译一部分。
3. 调用方用 `msg.In(locale)` 或 `usererror.Error.Text(locale)` 渲染。请求的语言可以用
   `i18n.WithLocale(ctx, locale)` 放进 context，再用 `i18n.LocaleFromContext(ctx)` 取出。

## 不属于文案的内容

指令触发词和别名表、解析关键字、游戏主数据名称、日志、内部错误原因留在代码里，
详见 AGENTS.md §12.6。copylint 对只放解析表的路径有白名单；其他位置单行在行尾写
`//copylint:ignore <原因>`，整张表在声明的注释里写 `//copylint:ignore-block <原因>`。
